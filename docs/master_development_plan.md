## 2. 핵심 전략

### 2.1 시뮬레이션 우선 개발 원칙

장치(외골격 로봇)가 아직 완전히 구현되지 않은 현실을 고려한다.

```
┌──────────────────────────────────────────────────────┐
│              입력 계층 추상화 구조                      │
│                                                      │
│  [실제 장치]          [시뮬레이션]                     │
│  Bluetooth Serial  │  슬라이더 UI                    │
│  → 각도 스트림      │  → 동일한 각도 스트림            │
│         ↓          │         ↓                      │
│      AngleNormalizer (0.0 ~ 1.0)                    │
│              ↓                                      │
│          게임 로직 (동일)                             │
└──────────────────────────────────────────────────────┘
```

**현재 이미 구현됨**: 각 게임에 `_isSim` 플래그 + 슬라이더 UI  
**추가 필요**: 사전 녹화된 동작 재생 모드 (발표용 자동 시연)

### 2.2 품질 우선 순위

```
1순위: 데모 완성도 (2026-05-08 발표)
2순위: 전체 게임 그래픽 완성 (2026-10)
3순위: 장치 연동 안정화 (2027-02)
4순위: 임상 검증 (2027-03~08)
5순위: 최종 패키징 (2027-11)
```

## 5. Phase 3 — 장치 연동 통합 (2027-03-01 ~ 2027-06-30)

> **현실적 전제**: 외골격 하드웨어 완성 시점에 따라 시작 시점 유동적. 하드웨어 미완성 시 BT 프로토콜 시뮬레이터 먼저 구현.

### 5.1 현재 연동 구조

```
[외골격 로봇] ←Bluetooth Serial→ [Jetson] ←BT→ [태블릿 앱]

송신 (앱→로봇):
  "mode:S\n"          정지
  "PART:lElbow\n"     관절 선택
  "CPM,min,max,vel\n" CPM 운동 시작
  "isometric,angle,holdTime\n"

수신 (로봇→앱):
  "45.2\n"            각도값 (°)
```

### 5.2 Phase 3 작업 목록

| 항목 | 내용 | 예상 기간 |
|------|------|-----------|

| ROM 캘리브레이션 UI | 환자별 관절 가동 범위 측정 플로우 | 2주 |
| 연결 끊김 자동 감지 | watchdog 타임아웃 → 안전 정지 + 재연결 | 1주 |
| 세션 데이터 로깅 | session_logger.dart — 타임스탬프별 각도, 이벤트 CSV | 2주 |
