## 1. 이 프로젝트가 왜 중요한가

뇌졸중(Stroke)은 뇌혈관이 막히거나 터지면서 발생하는 질환입니다. 뇌졸중 후 많은 환자들이 한쪽 팔을 제대로 움직이지 못하는 편마비(Hemiplegia) 상태가 됩니다.

회복을 위해서는 팔을 반복적으로, 정확하게 움직이는 훈련이 필요합니다. 그런데 이 훈련은 단조롭고 힘들어서 환자들이 중도에 포기하는 경우가 많습니다.

이 프로젝트는 **재활 훈련을 게임으로 만드는 것**입니다. 환자가 팔을 움직이면 게임이 반응하고, 필요할 때 보조 모터가 팔을 도와줍니다. 태블릿 화면을 보며 게임을 하다 보면, 어느새 재활 운동을 하고 있는 구조입니다.

여러분이 작성한 코드는 실제 임상 현장에서 환자에게 사용됩니다. 게임이 더 매끄러울수록 환자가 더 오래, 더 즐겁게 재활에 참여하게 됩니다.

## 2. 시스템이 어떻게 동작하는가

### 환자 회복 단계 — Brunnstrom Scale

뇌졸중 회복은 단계가 있습니다. 앱은 환자의 회복 단계에 맞춰 게임 난이도를 자동으로 조정합니다.

| 단계 | 상태 | 게임 방식 |
|------|------|---------|
| 2 | 경직 시작 | 모터가 팔을 대신 움직여줌 (CPM, 수동 보조) |
| 3 | 공동운동 패턴 | 허용된 움직임 범위 안에서 게임 |
| **4** | **공동운동 분리 시작** | **핵심 단계 — 독립적 관절 제어를 유도하는 게임** |
| 5 | 독립적 관절 운동 | 정밀 제어 + 복합 관절 게임 |
| 6 | 정상에 가까움 | 실제 일상생활 동작 시뮬레이션 |

### 타겟 관절 3가지

모든 게임은 아래 관절 중 하나(또는 여러 개)를 사용합니다.

| 코드 | 관절 | 일상생활 연계 |
|------|------|------------|
| `lShoulderEF` | 어깨 굽힘/폄 (Flexion/Extension) | 선반 위 물건 잡기 |
| `lShoulderRo` | 어깨 내/외회전 (Rotation) | 문손잡이 돌리기 |
| `lElbow` | 팔꿈치 굽힘/폄 | 식사, 양치, 빗질 |

### 데이터 흐름

```
블루투스 센서 → 원시 각도(°)
  → AngleNormalizer (0.0~1.0으로 정규화)
    → GameConfig (Brunnstrom·인지레벨·모터 설정 적용)
      → 게임 루프 (Flutter + Flame 엔진)
        → 모터 명령 전송 (GameMotorController)
```

### GameConfig — 난이도 자동 조정

게임 난이도를 일일이 설정하지 않습니다. `GameConfig` (`lib/games/game_base.dart`)가 세 가지 입력값으로 모든 것을 자동 계산합니다.

- **BrunnstromStage** (2~6): ROM 범위, 게임 속도, 모터 보조 여부
- **CognitiveLevel** (1~3, MMSE 점수 기반): 오브젝트 크기, 파티클 효과, 타이머 표시 여부
- **MotorMode**: `none` / `cpm` (수동) / `isometric` (유지) / `isotonic` (저항)

## 3. 현재까지 개발된 게임 (12개)

### 어깨 게임 (Shoulder)

| ID | 게임명 | 관절 | 재활 목표 | 일상생활 연계 | 상태 |
|----|--------|------|---------|------------|------|
| S1 | 하늘 정원사 | 어깨 굽힘/폄 | ROM 확대 | 선반 물건 잡기 | ⏳ |
| S2 | 구름 위 화가 | 어깨 전체 ROM | 균일한 ROM 사용 | 칠판 쓰기 | ⏳ |
| S3 | 방패 막기 | 어깨 굽힘/폄 | 등척성 유지 | 팔 들고 버티기 | 🔄 |
| S4 | 금고 털이범 | 어깨 내/외회전 | 공동운동 분리 | 문손잡이 돌리기 | ⏳ |
| S6 | 수영 선수 | 어깨 굽힘/폄 | 수직 반복 | 선반/세면대 도달 | ⏳ |

### 팔꿈치 게임 (Elbow)

| ID | 게임명 | 관절 | 재활 목표 | 일상생활 연계 | 상태 |
|----|--------|------|---------|------------|------|
| E1 | 벽돌 깨기 | 팔꿈치 굽힘/폄 | 정밀 ROM | 테이블 위 조작 | ⏳ |
| E2 | 목공 장인 | 팔꿈치 굽힘/폄 | 반복 ROM | 톱질·빗질 | ⏳ |
| E3 | 물약 제조 | 팔꿈치 굽힘/폄 | 등척성 유지 | 컵 들고 버티기 | ⏳ |

### 복합 관절 게임 (Combined)

| ID | 게임명 | 관절 | 재활 목표 | 일상생활 연계 | 상태 |
|----|--------|------|---------|------------|------|
| C1 | 시계 도달 | 어깨 또는 팔꿈치 | 8방향 도달 | 자유 탐색 | ⏳ |
| C2 | 식사 도우미 | 어깨 + 팔꿈치 | 2단계 순서 동작 | 실제 식사 | ⏳ |
| C3 | 볼링 마스터 | 팔꿈치(조준) + 어깨(스윙) | 다관절 협응 | 던지기·밀기 | ⏳ |

**상태 표기**: ✅ 완성 · 🔄 진행 중 · ⏳ 미착수

> **방패 막기 [S3]** 가 가장 개발이 진행된 게임입니다. 코드 패턴을 파악할 때 이 게임을 먼저 읽어보세요.

## 5. 첫 번째 기여 과제

아래 세 가지 과제는 서로 독립적이고, 각각 그 자체로 완결된 기여입니다. 전체 코드베이스를 이해하지 않아도 시작할 수 있습니다.

---

### Task A — 게임 테스트 & 버그 리포트 (1~2일)

**할 일**: 앱의 모든 게임을 직접 실행하고 이상한 점을 기록합니다.

찾아볼 것:
- 읽기 어렵거나 이상한 텍스트
- 반응하지 않는 버튼
- 충돌하거나 멈추는 게임
- 태블릿을 처음 보는 환자가 혼란스러워할 만한 UI

**리포트 방법**: GitHub Issues에 하나씩 등록. 제목은 `[게임ID] 짧은 설명` 형식으로 (예: `[S3] 화살이 방패 뒤로 사라짐`).

**왜 중요한가**: 처음 보는 눈으로만 찾을 수 있는 문제들이 있습니다. 임상 현장의 환자와 치료사는 훨씬 나중에야 피드백을 줄 수 있습니다. 지금 이 피드백은 매우 가치 있습니다.

**시작 전**: `docs/CHANGELOG.md`를 읽고 최근에 무엇이 바뀌었는지 확인하세요.

---

### Task B — 방패 막기 효과음 추가 (3~5일)

**할 일**: 방패 막기 [S3]에는 아직 소리가 없습니다. 타격음, 방어음, 배경 음악을 추가합니다.

**순서**:
1. 무료 `.mp3` 파일 찾기 (freesound.org, kenney.nl 등 CC0 라이선스)
2. `assets/audio/sheild_guard/` 폴더에 파일 복사 (폴더명 오타 그대로 유지)
3. `pubspec.yaml` 의 `flutter: assets:` 에 경로 등록
4. `lib/games/games/shield_guard_game.dart` 에서 게임 이벤트 발생 시 `FlameAudio.play('파일명.mp3')` 호출

**참고 문서**: `docs/shield_guard_build_guide.md` — 게임 구조 전체 설명 있음

**왜 중요한가**: 인지 레벨 1 환자(MMSE < 20)는 텍스트보다 소리로 피드백을 더 잘 받아들입니다. 소리 하나가 재활 효과를 바꿀 수 있습니다.

---

### Task C — 결과 화면 한/영 다국어 처리 (1주)

**할 일**: 게임 종료 후 점수와 정확도를 보여주는 결과 화면(`lib/games/game_result_screen.dart`)에 한국어/영어 전환을 추가합니다.

**방법**: 앱에 이미 언어 설정이 있습니다. 다른 화면에서 언어를 어떻게 처리하는지 검색해서 (예: `AppLocalizations` 또는 locale 변수) 같은 패턴을 결과 화면에 적용하면 됩니다.

**왜 중요한가**: 이 화면은 12개 게임 모두에서 사용됩니다. 변경 한 번으로 전체 게임에 적용됩니다.

## 6. 알아야 할 핵심 파일

| 파일 | 역할 |
|------|------|
| `lib/games/game_base.dart` | 핵심 타입 정의 — `BrunnstromStage`, `GameConfig`, `GameResult`, `AngleRecord` |
| `lib/games/games/shield_guard_game.dart` | 완성도 가장 높은 게임 — 코드 패턴 참고용 |
| `lib/games/angle_normalizer.dart` | 블루투스 각도 → 0.0~1.0 정규화 |
| `lib/games/game_motor_controller.dart` | 모터 명령 전송 (블루투스) |
| `lib/games/game_result_screen.dart` | 모든 게임 종료 후 결과 화면 |
| `docs/claude_code_game_dev_guide.md` | 이 프로젝트의 개발 패턴 및 규칙 |
| `docs/CHANGELOG.md` | 최신 변경 이력 — 먼저 읽어보세요 |
| `docs/master_development_plan.md` | 전체 일정 및 Phase 구분 |

> **단독 수정 금지**: `game_base.dart`와 `game_motor_controller.dart`는 전체 게임에 영향을 줍니다. 수정 전 반드시 팀과 협의하세요.

## 7. 도움 요청하는 방법

1. `docs/CHANGELOG.md` 확인 → 내가 작업할 부분이 최근에 어떻게 바뀌었는지 파악
2. 해당 게임의 `docs/*_build_guide.md` 먼저 읽기
3. 구체적인 질문으로 물어보기

**좋은 질문 예시**: "shield_guard_game.dart 82번째 줄에서 `_holdTimer`가 팔이 임계값 아래로 내려가면 리셋되는데, 의도된 동작인가요 아니면 버그인가요?"

**덜 도움이 되는 질문**: "게임 코드를 전혀 모르겠어요."
