# 상지 재활 게임 개발 전략 및 일정

## 1. 대상 환자 및 임상 배경

### 1.1 편마비(Hemiplegia) 환자 특성

뇌졸중 후 편마비 환자의 상지 회복은 Brunnstrom 6단계를 따른다:

| 단계 | 특성 | 게임 적용 |
|------|------|----------|
| Stage 1 | 이완기 — 수의적 움직임 없음 | 게임 적용 불가 (CPM 수동 운동만) |
| Stage 2 | 경직 시작 — 연합 반응, 최소 수의 운동 | CPM 보조 게임 (수동적) |
| Stage 3 | 경직 증가 — 공동운동(synergy) 패턴 출현 | 공동운동 패턴 내 게임 (굽힘/폄 시너지) |
| **Stage 4** | **경직 감소 — 공동운동에서 벗어나는 움직임 시작** | **핵심 타겟: 분리 운동 유도 게임** |
| **Stage 5** | **독립적 관절 운동 가능** | **정밀 제어 + 복합 관절 게임** |
| Stage 6 | 정상에 가까운 운동 | ADL 시뮬레이션 게임 |

### 1.2 상지 공동운동 패턴 (Synergy Pattern)

편마비 환자의 비정상적 공동운동 — 게임 설계의 핵심 기초:

```
■ 굽힘 공동운동 (Flexor Synergy):
  어깨 벌림 + 팔꿈치 굽힘 + 아래팔 뒤침
  → 팔을 올리면 팔꿈치가 자동으로 구부러지는 패턴

■ 폄 공동운동 (Extensor Synergy):
  어깨 모음 + 팔꿈치 폄 + 아래팔 엎침
  → 팔을 내리면 팔꿈치가 자동으로 펴지는 패턴
```

**게임 설계 원칙**: Stage 3~4 환자에게는 공동운동 패턴 "내에서" 시작하여 점진적으로 패턴을 "분리"하는 방향으로 게임 난이도를 설계해야 한다.

### 1.3 대상 관절 및 운동

현재 외골격 로봇이 지원하는 3개 관절:

| 관절 코드 | 관절 | 운동 | 편마비 재활 의의 |
|-----------|------|------|----------------|
| `lShoulderEF` | 어깨 굽힘/폄 | 팔 올리기/내리기 | ADL 핵심: 물건 잡기, 선반 닿기 |
| `lShoulderRo` | 어깨 내회전/외회전 | 팔 안쪽/바깥쪽 돌리기 | 공동운동 분리 핵심 운동 |
| `lElbow` | 팔꿈치 굽힘/폄 | 팔 구부리기/펴기 | 식사, 양치, 빗질 등 ADL |

## 2. 게임 설계 철학

### 2.1 핵심 원칙

1. **관절별 전용 게임**: 각 게임은 특정 관절 운동에 최적화. "어깨 게임"과 "팔꿈치 게임"을 구분
2. **Brunnstrom 단계 연동**: 같은 게임이라도 환자 회복 단계에 따라 보조력/저항/ROM 범위 자동 조절
3. **ADL 시뮬레이션**: 게임 메카닉이 일상생활동작(밥 먹기, 물건 잡기, 문 열기)과 유사한 운동 패턴
4. **공동운동 인식**: Stage 3~4 환자의 공동운동 패턴을 존중하되, 분리 운동을 점진적으로 유도
5. **양방향 모터 연동**: 게임이 센서 데이터를 읽을 뿐 아니라, 모터에 보조/저항 명령을 전송
6. **인지 수준 적응**: 인지장애 환자를 위한 시각 단순화 모드 제공

### 2.2 인지 수준별 시각 디자인 체계

뇌졸중 편마비 환자의 약 30~50%는 인지장애를 동반한다. 주의력 저하, 시공간 무시(편측 무시), 기억력 감소, 실행 기능 장애가 흔하며, 게임이 시각적으로 복잡하면 오히려 혼란과 좌절감을 유발한다.

#### 인지 레벨 3단계 분류

게임 시작 전 의료진이 환자의 인지 레벨을 설정 (Brunnstrom 단계와 독립적):

| 인지 레벨 | 대상 | 시각 특성 | 게임 특성 |
|-----------|------|----------|----------|
| **레벨 1: 단순** | MMSE < 20, 심한 인지장애 | 최소 요소, 고대비, 큰 오브젝트 | 1가지 동작만, 즉각 피드백 |
| **레벨 2: 보통** | MMSE 20~25, 경도 인지장애 | 적당한 요소, 명확한 색 구분 | 2~3가지 규칙, 점수 표시 |
| **레벨 3: 풍부** | MMSE > 25, 인지 정상 | 풍부한 이펙트, 파티클, 배경 | 복합 규칙, 콤보, 전략 |

#### 레벨별 구체적 시각 차이

```
■ 레벨 1 (단순 모드):
  - 배경: 단색 (검정 또는 흰색)
  - 오브젝트: 2~3개 이하, 크기 2배
  - 색상: 빨강/파랑/초록 고대비 원색만 사용
  - 파티클/이펙트: 없음 — 시각 산만 방지
  - 텍스트: 점수만 표시 (큰 글씨), 타이머/콤보 숨김
  - HUD: 최소화 — 게임 캔버스만 최대
  - 지시: TTS 음성 안내 자동 ("위로 올려주세요", "잘했어요")
  - 타겟: 단일 타겟만, 색상 점멸로 위치 강조
  - 속도: 매우 느림, 충분한 반응 시간

■ 레벨 2 (보통 모드):
  - 배경: 단순한 그라디언트 배경
  - 오브젝트: 4~6개, 표준 크기
  - 색상: 뚜렷한 색상 팔레트 (5~8색)
  - 파티클: 히트 시만 간단한 파티클 (5개 이하)
  - 텍스트: 점수 + 타이머 표시
  - HUD: 표준
  - 지시: 시작 시 TTS 안내, 게임 중은 시각 피드백만
  - 타겟: 2~3개 동시, 크기 강조
  - 속도: 보통

■ 레벨 3 (풍부 모드 — 기본값):
  - 배경: 테마 배경 (우주, 정원, 성벽 등)
  - 오브젝트: 제한 없음
  - 색상: 풍부한 색상 + 그라디언트 + 광택
  - 파티클: 수집/파괴 시 15~20개 파티클 폭발
  - 텍스트: 점수 + 타이머 + 콤보 + 실시간 피드백
  - HUD: 전체 — 목숨, 콤보, 진행도
  - 지시: 없음 (자율적 플레이)
  - 속도: 난이도에 따라 빠름
```

#### 편측 무시(Unilateral Neglect) 대응

편마비 환자의 약 25%가 환측 시야를 무시하는 편측 무시 증상이 있다:

```
[편측 무시 설정]
  - 의료진이 환측 방향 설정 (왼쪽/오른쪽)
  - 게임 오브젝트를 환측에 더 많이 배치 → 무시 영역 주의 유도
  - 환측 히트 시 보너스 점수 부여
  - 점진적으로 환측 비율 증가 (50% → 60% → 70%)
```

#### 구현 방식

각 Flame 게임 클래스에 `cognitiveLevel` (1~3) 파라미터 추가:

```dart
class GameConfig {
  AngleNormalizer normalizer;
  int difficultyLevel;         // 운동 난이도 (Brunnstrom 기반)
  int cognitiveLevel;          // 인지 레벨 (1=단순, 2=보통, 3=풍부)
  String bodyPart;
  Duration gameDuration;
  String? neglectSide;         // 편측 무시 방향 ('left' / 'right' / null)
}
```

게임 내에서 레벨에 따라 분기:

```dart
// 파티클 수 결정
int particleCount = [0, 5, 15][config.cognitiveLevel - 1];

// 배경 결정
Color bgColor = config.cognitiveLevel == 1
    ? Colors.black                    // 단순: 검정 배경
    : config.cognitiveLevel == 2
        ? const Color(0xFF1a1a2e)     // 보통: 어두운 남색
        : gameThemeColor;             // 풍부: 테마별 색상

// 오브젝트 크기 배율
double sizeMultiplier = [2.0, 1.2, 1.0][config.cognitiveLevel - 1];

// HUD 표시 범위
bool showCombo = config.cognitiveLevel >= 2;
bool showTimer = config.cognitiveLevel >= 2;
bool showLives = config.cognitiveLevel >= 3;

// TTS 음성 가이드
bool autoVoiceGuide = config.cognitiveLevel <= 2;
```

#### 상용 재활 시스템의 검증된 게임 유형 (2025 기준)

| 시스템 | 대표 게임 | 핵심 메카닉 | 임상 근거 |
|--------|----------|-----------|---------|

| **MediTouch ArmTutor** | 다방향 도달 게임 | 어깨 굽힘/폄+회전 통합 | 웨어러블 연동 |
| **연구 문헌 (42개 RCT)** | 스포츠 게임 (14), 슈팅 (7) | 타격, 투척, 볼링 메카닉 | Meta-analysis, 1,760명 |

#### 관절 방향과 게임 축 대응 원칙

편마비 환자의 운동 재학습은 **게임 컨트롤 방향이 실제 관절 운동 방향과 일치**할 때 신경가소성이 극대화된다.

| 관절 | 실제 운동 | 자연스러운 게임 축 | 잘못된 예 |
|------|---------|-----------------|---------|
| `lShoulderEF` | 팔 **위/아래** | 화면 **높이(Y축)** 제어 | 좌우(X축) 우주선 ❌ |
| `lShoulderRo` | 아래팔 **회전** | 화면 내 **회전각** 제어 | 좌우 이동 ❌ |
| `lElbow` | 팔꿈치 **굽힘/폄** | **접근/후퇴** 또는 높이 | 좌우 패들(직관성 낮음) ⚠️ |

#### 임상적으로 가장 효과적인 게임 요소 (99개 파라미터 중 상위 4개)

1. **환자 동기 부여 증대** — 성취감을 주는 즉각적 보상
2. **적응형 난이도** — 실시간 성공률 기반 자동 조절
3. **즐거움과 매력** — 테마, 스토리, 시각적 쾌감
4. **멀티모달 피드백** — 시각+청각 동시 (햅틱은 로봇이 담당)

### 3.2 어깨 게임 상세

#### [S1] 하늘 정원사 (Sky Gardener)
**관절**: 어깨 굽힘/폄 (`lShoulderEF`)
**메카닉**: 하늘 정원에서 다양한 높이에 매달린 과일/꽃을 관절 각도로 손을 뻗어 수확. 어깨를 올리면 위쪽 과일, 내리면 아래쪽 과일에 닿음.

| Brunnstrom 단계 | 게임 적응 |
|----------------|----------|
| Stage 2~3 | CPM 보조 + 넓은 타겟 (전체 ROM의 60% 이내) + 느린 과일 스폰 |
| Stage 4 | 보조력 감소 + 중간 타겟 + 공동운동 분리 유도 (팔꿈치 고정 상태에서 어깨만 움직이기) |
| Stage 5~6 | 보조 없음 + 좁은 타겟 + 빠른 스폰 + 정확도 보너스 |

**모터 연동**:
- 게임 시작: `PART:lShoulderEF\n`
- Stage 2~3: `cpm,<max>,<min>\n` (보조 모드로 부드러운 가이드)
- Stage 4+: 보조 없이 자유 운동, 각도 읽기만
- 긴급정지: `x\n`

**시각 디자인**: 수직 정원 배경. 위쪽은 해바라기/사과(고득점), 아래쪽은 풀/딸기(저득점). 수확 시 꽃잎 파티클 + 바구니에 담기는 애니메이션. 계절이 변하는 배경(봄→여름→가을).

**재활 가치**: 어깨 굽힘/폄 ROM 확대. ADL 중 "선반 위 물건 잡기"와 동일한 운동 패턴.

#### [S2] 구름 위 화가 (Cloud Painter)
**관절**: 어깨 굽힘/폄 (`lShoulderEF`) 또는 어깨 회전 (`lShoulderRo`)
**메카닉**: 하늘 캔버스에 무지개색 구역이 표시됨. 관절을 움직여 붓으로 칠한다. 전체 ROM 영역을 골고루 칠해야 높은 점수. 한쪽만 반복하면 점수가 낮아짐.

**핵심 치료 목표**: 편마비 환자가 특정 각도 범위만 반복 사용하는 경향(편향)을 교정. 사용하지 않는 ROM 영역으로 유도.

**시각 디자인**: 푸른 하늘 + 구름 배경. 칠해야 할 영역이 점선으로 표시. 칠한 부분은 무지개색으로 채워짐. 완성도% 표시. 100% 달성 시 폭죽 + 무지개 애니메이션.

**모터 연동**: ROM 측정과 병행 — 게임 중 달성한 최대/최소 각도가 자동으로 ROM 기록에 반영.

#### [S3] 방패 막기 (Shield Guard)
**관절**: 어깨 굽힘/폄 (`lShoulderEF`)
**메카닉**: 화면의 다양한 높이에서 화살/공이 날아옴. 방패(어깨 각도)를 해당 높이에 맞추고 **일정 시간 유지**해야 막기 성공.

**핵심 치료 목표**: 어깨 등척성 근력 강화. 특정 각도에서 자세 유지.

**모터 연동**:
- 목표 각도에서 등척성 저항: `isometric,<targetAngle>,<holdTime>\n`
- 모터가 해당 각도에서 약간의 저항을 주어, 환자가 근력으로 버텨야 함
- 난이도에 따라 저항 증가

**시각 디자인**: 중세 성벽 배경. 화살이 날아오는 방향 표시. 방패가 올바른 위치에 있으면 파란 게이지 충전. 완전 방어 시 화살이 튕겨나감 + 불꽃 이펙트. 미방어 시 성벽 손상.

#### [S4] 금고 털이범 (Safe Cracker)
**관절**: 어깨 내회전/외회전 (`lShoulderRo`)
**자세 전제**: 팔꿈치 90° 굽힘 고정 상태에서 어깨만 안쪽/바깥쪽으로 돌림

```
[운동 자세]
                 ↑ 외회전 (바깥 돌림)
                 │
 ── 팔꿈치 90° ──┤── 아래팔 수평 ──→
                 │
                 ↓ 내회전 (안쪽 돌림)

 ※ 팔꿈치는 90° 굽힘으로 고정
 ※ 상완(위팔)의 회전축만 사용
 ※ 편마비 공동운동 분리의 핵심 운동
```

**메카닉**: 화면에 금고 다이얼이 표시됨. 어깨를 외회전/내회전하여 다이얼을 돌려 목표 숫자에 맞춘다. 올바른 조합을 입력하면 금고가 열리고 보물 획득.

- 각 금고마다 2~4개의 목표 숫자 조합
- 다이얼을 목표 위치로 돌린 후 잠시 유지(1~3초) → 잠금 해제 소리 + 다음 숫자로
- 전체 조합 성공 → 금고 오픈 → 보물(금화/보석) 파티클
- 시간 제한 내 여러 금고를 열면 높은 점수

| Brunnstrom 단계 | 게임 적응 |
|----------------|----------|
| Stage 3 | CPM 보조 회전 + 넓은 목표 범위(±15°) + 2숫자 조합 + 유지 1초 |
| Stage 4 | 최소 보조 + 중간 범위(±10°) + 3숫자 조합 + 유지 2초 |
| Stage 5~6 | 보조 없음 + 좁은 범위(±5°) + 4숫자 조합 + 유지 3초 + 속도 보너스 |

**모터 연동**:
- 게임 시작: `PART:lShoulderRo\n`
- Stage 3: `cpm,<max>,<min>\n` (회전 보조)
- Stage 4+: 자유 운동 (각도 읽기만)
- 등척성 유지 요구 시: `isometric,<targetAngle>,<holdTime>\n` (목표 각도에서 저항)
- 긴급정지: `x\n`

**시각 디자인**: 은행 금고실 배경. 원형 다이얼이 화면 중앙에 크게 표시. 현재 어깨 회전 각도 = 다이얼 바늘 위치. 목표 숫자 영역이 강조 표시 (초록색 존). 잠금 해제 시 "찰칵" 효과음 + 기어 애니메이션. 금고 오픈 시 빛줄기 + 금화 쏟아지는 파티클.

**재활 가치**:
- **공동운동 분리 핵심 운동**: 팔꿈치 90° 고정 상태에서 어깨 회전만 독립적으로 수행 — 굽힘/폄 공동운동에서 회전을 분리하는 Stage 4의 핵심 치료 목표
- **고유수용감각 훈련**: 다이얼의 정밀 위치 조절 → 어깨 회전 위치 인식 향상
- **ADL 연계**: 문 손잡이 돌리기, 열쇠 돌리기, 수도꼭지 조작과 동일한 운동 패턴
- **양방향 회전**: 내회전→외회전을 번갈아 요구하여 양방향 ROM 균형 훈련

**난이도 상세**:
| 레벨 | 목표 범위 | 조합 수 | 유지 시간 | 시간 제한 | 모터 |
|------|----------|---------|----------|----------|------|
| 1 | ±20° | 2 | 1초 | 120초 | CPM 보조 |
| 2 | ±15° | 2 | 1.5초 | 90초 | 약한 보조 |
| 3 | ±10° | 3 | 2초 | 90초 | 없음 |
| 4 | ±7° | 3 | 2.5초 | 60초 | 약한 저항 |
| 5 | ±5° | 4 | 3초 | 60초 | 보통 저항 |

### 3.4 복합 관절 게임 상세

#### [C1] 시계 도달 (Clock Reaching) — 기존 Star Collector 대체 예정
**관절**: 어깨 굽힘/폄 (`lShoulderEF`) 또는 팔꿈치 (`lElbow`) 선택
**임상 근거**: InMotion ARM의 Clock Game — 상지 재활에서 가장 많이 연구된 단일 게임 유형

**메카닉**:
- 화면 중앙에서 8방향(시계 방향: 12시, 1시30분, 3시, ... ) 위치에 타겟이 순서대로 나타남
- 관절 각도 = 커서 위치 (어깨 굽힘 → 커서 위, 팔꿈치 굽힘 → 커서 오른쪽)
- 타겟에 커서를 올리면 수집 → 다음 타겟으로
- 한 바퀴(8타겟) = 1세트. 20세트 = 1세션(약 160회 반복)

**현재 Star Collector 문제**: 우주선이 좌우로만 이동 → 어깨 굽힘/폄의 위아래 운동과 불일치. 우선순위 높은 재설계 대상.

**시각 디자인**: 밝은 하늘 배경. 시계 숫자판처럼 배치된 8개 꽃. 커서는 나비. 타겟에 닿으면 꽃이 피는 애니메이션. 한 바퀴 완료 시 무지개 + 나비떼 파티클.

#### [C2] 식사 도우미 (Meal Helper)
**관절**: 어깨 + 팔꿈치 (관절 전환 게임)
**메카닉**: 식탁 위 음식을 입으로 가져가는 동작 시뮬레이션.
1. 1단계: 어깨 움직여 팔 뻗기 → 음식 위치에 닿기 (`lShoulderEF`)
2. 2단계: 팔꿈치 구부리기 → 음식을 입으로 가져오기 (`lElbow`)
3. 두 단계를 반복하며 다양한 음식 섭취

**임상 근거**: ADL 기반 게임이 가장 높은 재활 효과 — 식사 동작은 상지 재활의 핵심 목표.

**시각 디자인**: 식탁 조감도. 접시 위 다양한 음식 (밥, 반찬, 국). 젓가락/숟가락이 음식에 닿으면 잡기 애니메이션. 입으로 가져가면 "냠냠" 이펙트 + 만족도 게이지.

**관절 전환 프로토콜**:
```
1단계 시작: "PART:lShoulderEF\n" → 어깨 각도 읽기
1단계 성공: "x\n" (어깨 정지)
2단계 시작: "PART:lElbow\n" → 팔꿈치 각도 읽기
2단계 성공: "x\n" (팔꿈치 정지) → 점수 + 다음 음식
```

**재활 가치**: 실제 식사 동작과 동일한 관절 시퀀스 훈련. 어깨→팔꿈치 연계 운동. 공동운동 패턴 분리 연습 (어깨를 움직일 때 팔꿈치 고정, 팔꿈치를 움직일 때 어깨 고정).

#### [C3] 볼링 마스터 (Bowling Master) ✅ 구현 완료
**관절**: 팔꿈치 굽힘/폄 (`lElbow`) + 어깨 굽힘/폄 (`lShoulderEF`) → `combinedGames` 카테고리
**운동**: 팔꿈치 정밀 조준 + 어깨 동적 스윙(Extension→Flexion) 복합
**임상 근거**: 
- 실제 볼링 투구와 동일한 다관절 운동 시퀀스 — ADL(던지기, 물건 밀기) 복원
- **팔꿈치-어깨 관절 분리 훈련**: 어깨가 스윙하는 동안 팔꿈치 위치를 고정 → 공동운동 패턴 분리의 핵심 (Stage 4~5 핵심 치료 목표)
- 어깨 동적 ROM + 가속도 제어: 발사력이 스윙 속도에 비례 → 기능적 운동 회복

**실제 볼링 동작과의 대응**:
```
실제 볼링:  조준(방향) → 백스윙(팔 뒤로) → 포워드스윙(팔 앞으로) → 릴리즈
게임 관절:  팔꿈치 조준 → 어깨 폄(Extension) → 어깨 굽힘(Flexion) → 자동 발사
```

**메카닉 (관절 전환 4단계 사이클)**:
1. **조준 (Aiming)** — `PART:lElbow\n`: 팔꿈치 굽힘/폄 → 공 좌우(X) 위치 제어. 원하는 방향으로 조준 후 1초 유지 → 조준 확정
2. **백스윙 (Backswing)** — `PART:lShoulderEF\n`: 어깨를 뒤로 폄(Extension zone, 정규화 0.2 이하). 시각: 볼러가 팔을 뒤로 당기는 애니메이션
3. **포워드스윙 + 발사 (Release)**: 어깨 굴곡(Flexion) 방향으로 빠르게 이동. 각도 변화율(dAngle/dt)이 임계값 초과 → 자동 발사. **발사 속도 = 어깨 스윙 속도**
4. **결과 (Result)**: 핀 충돌 판정 + 스코어 → 0.8s 대기 → 핀 재배치 → Step 1 복귀

**관절 전환 프로토콜**:
```
Step 1: "PART:lElbow\n"      → 팔꿈치 각도 읽기 (조준)
Step 1 확정: "x\n"           → 팔꿈치 정지, 조준 X 위치 잠금
Step 2~3: "PART:lShoulderEF\n" → 어깨 각도 읽기 (스윙 감지)
발사 후: "x\n"               → 어깨 정지
프레임 리셋 후: "PART:lElbow\n" → 조준 재시작
```

**에셋**:
- 배경: `_LaneBackground` (나무 그라디언트 + 레인 라인 + 핀 존)
- 볼링공: `kenney_space-shooter-redux/PNG/Meteors/meteorBrown_big1.png`
- 볼링 핀: `_BowlingPin` custom draw (흰색 타원 + 빨간 줄무늬)
- 조준선: `_AimLine` (점선, 팔꿈치 단계에서만 표시)
- 스윙 게이지: `_SwingMeter` (어깨 폄 → 충전, 굴곡 속도 → 발사)

**Brunnstrom / 인지 레벨 적응**:

| 파라미터 | Stage 2~3 | Stage 4~5 | Stage 6 |
|---------|-----------|-----------|---------|
| 팔꿈치 조준 존 | 화면 80% | 60% | 45% |
| 발사 임계 속도 | 낮음 (0.5/s) | 보통 (1.0/s) | 높음 (1.8/s) |
| 핀 히트 반경 | 45px | 30px | 20px |
| 조준 유지 시간 | 0.5s | 1.0s | 1.5s |

| 인지 레벨 | 핀 배열 | 보조 |
|-----------|--------|------|

**재활 가치**:
- **다관절 협응**: 어깨-팔꿈치 분리 운동 → 공동운동 패턴 극복의 핵심
- **동적 ROM + 등척성 혼합**: 조준(유지) + 스윙(동적) 순서로 두 운동 패턴 교대
- **ADL 연계**: 물건 던지기, 밀기, 선반 위 물건 조작과 유사한 어깨 굴곡 운동

#### [C4] 오브젝트 치기/피하기 (Object Hit & Avoid) — 미래 확장 (기존 Gate Runner 대체)
**관절**: 선택 가능
**임상 근거**: KINARM의 Object Hit and Avoid — 운동 제어 + 선택적 주의력 동시 훈련. 편마비 후 인지-운동 복합 재활에 효과적.

**메카닉**:
- 화면 위에서 다양한 오브젝트가 내려옴
- **빨간 오브젝트**: 커서를 올려 터뜨리기 (+점수)
- **파란 오브젝트**: 피하기 (터뜨리면 -점수)
- 관절 각도 = 커서 좌우 위치 (또는 높이)
- 인지 레벨 1: 한 종류만(치기만), 레벨 2~3: 두 종류 구분

**현재 Gate Runner 문제**: 게이트 통과만 요구 → 인지 부하 없음, 단순 추적만 훈련. 오브젝트 구분을 통한 선택적 주의력 훈련으로 업그레이드 필요.

**시각 디자인**: 밝은 바다 배경. 열대어(치기)와 해파리(피하기). 인지 레벨 1은 열대어만. 터뜨리면 물방울 파티클. 해파리 건드리면 전기 이펙트 + 점수 감소.

## 10. 3D 게임 확장 방안

### 10.1 Flutter + Flame의 3D 지원 현황

Flame 1.36.0은 완전한 **2D 전용 엔진**이다. 3D 렌더링을 추가하려면 별도 패키지가 필요하다.

| 패키지 | 주간 다운로드 | 최신 업데이트 | 모델 형식 | 상태 |
|--------|-------------|-------------|---------|------|
| `flutter_3d_controller` | **4,890** | 2025-09 | GLB, GLTF, OBJ, FBX | ✅ 프로덕션 |
| `flutter_scene` | 620 | 2024-06 | glTF (Impeller 필요) | ✅ iOS/Android |
| `thermion_flutter` | 165 | 2025-09 | glTF, KTX (Filament) | ✅ 전 플랫폼 |
| `flame_3d` | 85 | 2025-03 | 자체 형식 | ❌ 실험적 |
| `three_dart` | 318 | **2022-11** | GLTF, GLB | ❌ **방치됨** |
| `flutter_cube` | — | **2021-03** | OBJ만 | ❌ 사실상 폐기 |

**권장: `flutter_3d_controller`** — 가장 활발히 유지관리(주간 4,890 다운로드, 2025년 9월 최신 업데이트). GLB/GLTF/FBX 직접 로딩, Android 태블릿 검증. `kenney_food-kit` GLB 모델과 즉시 호환.

### 10.2 기존 3D 에셋 현황

`assets/kenney_food-kit/Models/GLB format/` — **201개 GLB 파일** (apple.glb, bowl.glb, fork.glb 등)
- 음식, 용기, 식기류 완비
- PBR 텍스처 포함 
- `flutter_3d_controller`로 즉시 로딩 가능

`assets/kenney_medieval-rts/PNG/` — 아이소메트릭 **2D** PNG 스프라이트 (3D 모델 없음)

### 10.3 재활 관점에서 2D vs 3D 비교

| 측면 | 2D (현행) | 3D (확장) |
|------|----------|---------|
| 인지 부하 | 낮음 — 공간 혼란 없음 | 높음 — 원근감, 깊이 인식 필요 |
| 적합 환자 | 인지 수준 1~3 전체 | **인지 수준 3 + Brunnstrom 5~6** |
| 개발 난이도 | 완료됨 | `flutter_3d_controller` 학습 곡선 추가 |
| ADL 현실감 | 중간 | 높음 (사실적 음식/물체) |
| 성능 | 60fps 보장 | 최대 500K 폴리곤에서 60fps 가능 |
| 배터리 소모 | 낮음 | 높음 — 30fps 제한 권장 |

**결론**: 인지 수준이 높은 환자(Stage 5~6)의 동기 부여와 ADL 현실감 향상을 위해 3D는 가치가 있으나, **현재 2D 10종 게임 완성이 우선**이다.

lib/widgets/model3d_viewer.dart  ← 공통 3D 렌더 위젯
  ├── Flutter3DController 초기화
  ├── GLB/GLTF 모델 비동기 로딩
  ├── BT 각도 → 오브젝트 회전/위치 매핑
  └── 애니메이션 재생 제어

  └─ Stack
       ├─ Flutter3DViewer (3D 오브젝트 레이어)

```

```
